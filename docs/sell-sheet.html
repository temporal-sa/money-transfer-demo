The money-transfer demo, read as Revedia’s workloads

This is Temporal’s standard demo, not a Revedia build. Watch the shape rather than the domain. A transfer is four steps in order (validate, withdraw, deposit, notify), each calling a system that can fail. That’s also an OTC response, an invoice posted to SAP, and a report working through its countries. The workflow and its steps are 219 lines of plain Java; every line in blue says what a step means for Revedia.

How to read it

  1. 1Failure handling is configuration. Each step’s timeouts and retries are declared once, on the stub. There’s no try/catch, retry loop or sleep anywhere in the workflow. Revedia: the same block wraps every call to SAP, the billing database or a partner’s endpoint.
  2. 2Per attempt: if the API hangs or the Worker dies mid-call, Temporal abandons that attempt after 5 s and tries again.
  3. 3Overall budget: every retry together gets 5 minutes. This, not a count of attempts, bounds the retries. Revedia: an SLA. Past it, the job fails visibly instead of silently.
  4. 4Back off: retry after 1 s, then 2, 4, 8 … up to 30 s between tries, so a struggling service gets room to recover. This is the API Downtime beat. Revedia: a rolling deploy or a brief 503 between services delays a message, it doesn’t lose it.
  5. 5Deposit is the long step, so it gets its own options.
  6. 6The hang detector. Deposit reports progress after every batch. If 5 s pass with no report, Temporal knows the Worker is gone or stuck, not just slow, and retries the step. Revedia: a 3-day report that stalls is caught in seconds, not found on day 3.
  7. 7One idempotency key per transfer, generated inside the workflow so it’s the same on every retry and replay. Downstream systems use it to apply a retried call once. Revedia: the key that stops a retried posting landing in SAP twice.
  8. 8Plain method calls, top to bottom. Each line is an Activity: Temporal records that it finished and retries it if it didn’t. A crash anywhere resumes at the next line, not the top. This is the Happy Path beat. Revedia: an OTC response is the same shape: parse, validate, store, match it to what you sent, update the database, update the UI.
  9. 9The heartbeating deposit, called like any other step.
AccountTransferActivitiesImpl.java

The long step: report progress, resume from it

The deposit posts in six batches and checks in with Temporal after each. Kill the Worker after batch 2 and the restarted Worker logs Deposit resuming after batch 2 of 6, then posts 3 to 6.

  1. 14A wait for a person, in one line. The workflow holds here until approval arrives or the window closes, whether that’s seconds or days. Waiting holds no Worker and no thread. This is the Human in the Loop beat. Revedia: finance approves the close before invoices go out; an accrual waits weeks for the distributor’s late statement.
  2. 15No approval in time is just a branch: fail with a reason, and it shows up in search. Revedia: a statement that never arrives is flagged, not forgotten.
  3. 16The bug. A code bug fails the workflow task, not the workflow: the transfer stays Running and keeps retrying, with the money safe after the withdraw. Fix the code, restart the Workers, and the stuck transfers finish on their own. This is the Bug in Workflow beat. Revedia: a wrong per-organization EDI rule: fix it and the stuck messages complete, with no manual replay or cleanup.
